Stop accidental drill-downs into records people shouldn't casually open

Pick exactly which models lose the Many2one “open linked record” arrow — without touching access rights, without writing code, and without affecting Kanban views.

1

Pick models, not fields

Add any model to a simple configuration list. Every Many2one pointing at records of that model has its click-through disabled — no per-field setup, no view inheritance to maintain.

2

Form & List only

The restriction is scoped to the model being displayed — its own Form and List views. Kanban views are never touched, whatever you configure.

3

One click to pause

Untick a model's Active toggle to lift the restriction instantly, or re-enable it later, without ever deleting the configuration entry.

Where the restriction applies

The rule is about the view being displayed, not the model the Many2one field points to. If hr.leave is restricted, every Many2one shown on an hr.leave Form or List loses its open-record arrow — regardless of what it links to.

View typeAffected by restriction?
Form viewRestricted when configured
List viewRestricted when configured
Kanban viewNever restricted

Setting it up

  1. Open the menu. Go to Ow Tools › Internal Link Restrictions (visible to users in the Settings / Technical Features group).
  2. Add a model. Create a new line and select the model whose Form and List views should lose the Many2one click-through. An optional note field lets you record why.
  3. Save, then refresh. The restricted-model list is pushed into the user session at login / page load, so anyone already connected needs to refresh their browser tab for a change to take effect.
  4. Toggle as needed. Flip a row's Active switch off to pause a restriction, or back on to reinstate it — the configuration entry itself is never lost.

Good to know before you configure anything

  • This is a client-side UI restriction only. It does not change ir.model.access.csv rights or ir.rule record rules. A user with read access to a restricted model can still reach its records through search, another menu, or a report. For real data-level security, use record rules.
  • The restricted-model list loads once per session (login / page load). After adding, removing, or toggling a model, users must refresh their tab to see the change.
